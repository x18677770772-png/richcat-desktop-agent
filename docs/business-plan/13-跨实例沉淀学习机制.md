# 13 · 跨实例沉淀学习机制：把"真实场景使用"变成工程飞轮

> 财听猫 RichCat ｜ AI 企业级客户服务与管理系统
> 角色：AI 工程师（ML 系统 / 数据管线 / 工程化）
> 基线：v1.1.0（2026-08-19）｜ 订阅优先（50 家 × ¥1–2 万/年，见 00/01 分卷）
> 配套分卷：00 总纲 / 02 产品企业级化路线（M1–M8、S3） / 10 数据合规与法务（PIPL 红线）
> 技术底座：[richcat-v2-design.md](../richcat-v2-design.md)（PromptAssembler 14 段 / FeatureHooks / F2 接管）｜ [learn-work-memory-plan.md](../plan/learn-work-memory-plan.md)（工作记忆 L1–L3）
> 定位：把创始人核心逻辑——**"只要有真实场景使用，就能加速产品迭代"**——从一句口号变成可度量、可回灌、可销售的工程机制。本分卷定义"学什么 / 不学什么 / 怎么学 / 学了怎么用 / 怎么证明有用"。

## 0. 执行摘要（先给结论）

**一句话：RichCat 的跨实例沉淀学习，是在"云侧不碰聊天原文"的合规铁律下，把全舰队每台值守机产生的脱敏行为数据（错误、用量、接管、成本、经验模板）聚合成公共资产，再以"模板/规则/配置"形态回灌每一台实例——让每一家客户的真实使用，都在让所有客户变得更好。**

三个关键判断：

1. **合规是地基，不是障碍。** 10 分卷铁律：中央云侧只承载元数据，不得汇聚客户聊天内容与个人信息（PIPL）。因此本机制**从设计上就不上报"事件原文"，只上报"脱敏聚合桶"**——不是事后脱敏，而是结构上就不产生原文上行。跨实例学习能聚合的，天然只有"行为统计 + 归一化错误 + 通用化经验模板"。
2. **经验学习是唯一差异化护城河。** 故障学习、使用学习、成本学习竞品也能抄，但"经客户同意的匿名化经验卡片 → 行业知识模板库 → 新实例 opt-in 回灌"这条回路，直接复用产品已有的工作记忆引擎（L3 继承层），是把"越用越懂你的业务"从单实例放大到行业的独家能力。
3. **没有度量闭环的学习机制是自嗨。** 本分卷把每个学习回路都绑定一个可量化 KPI，并用 A/B（启用全局经验 vs 不启用）+ 灰度下发证明"沉淀学习真的有效"——它是续费率从"话术"变成"证据"的工程基础。

**90 天目标锚点（对齐 00 分卷）：** 前 10 家战略伙伴 = 学习机制的冷启动舰队；W8 前跑通"本地采集 → 云侧聚合 → 模板回灌"的最小闭环；90 天末用 50 家实例产出首批"行业经验模板库 + 首份舰队学习报告"，并把"学习价值"做成可续约卖点。

## 1. 学习的目标定义：改进什么 + 北极星

### 1.1 跨实例学习要改进的五个对象（按优先级）

| 优先级 | 改进对象 | 为什么是它 | 谁来受益 |
|---|---|---|---|
| P0 | **回复质量（回复采纳率）** | 客户为"客服降本 50% + 客户被记住"买单；采纳率是质量的直接代理 | 客户（满意度）→ RichCat（续费） |
| P0 | **故障率（宕机/错误/自愈）** | SLA"敢承诺 ≥99%"的前提；值守机故障是"无人值守"最大的雷 | 客户（可用性）→ RichCat（口碑） |
| P1 | **API 成本（单条成本/模型路由）** | 团队版毛利 43–65% 对单条成本敏感（基准 ¥0.02，红线 ¥0.04） | RichCat（毛利）→ 客户（加量不涨价） |
| P1 | **产品功能优先级（砍/加功能）** | 数据驱动迭代：用热度/流失信号决定做什么，而非拍脑袋 | RichCat（研发效率）→ 客户（用对的功能） |
| P2 | **人机接管率（该接管的接管、可自处理的接管率）** | 接管是信任开关：接得太少客户担心、接得太多人力省不下来 | 客户（人力）→ RichCat（价值证明） |

### 1.2 北极星指标（North Star）

**北极星 = 舰队级「沉淀学习净价值」（Learning Net Value, LNV）**，定义为三个可量化维度的复合提升：

```
LNV = α · Δ回复采纳率 ↑  −  β · Δ接管率 ↓  −  γ · Δ单条API成本 ↓
（α/β/γ 为权重，首版取 0.5/0.3/0.2；各 Δ 为"启用全局学习 vs 未启用"的配对差值）
```

业务北极星（最终落点）：**启用全局学习的客户 续费率 ≥ 90%**，且 **NPS ≥ 40**——这是把"学习价值"翻译成钱。
工程北极星（每日可测）：**舰队学习回灌采纳率 ≥ 60%**（下发的模板/规则/告警中被实例实际启用的比例）。

### 1.3 90 天可量化目标表

| 维度 | 指标 | 90 天目标 | 数据来源 |
|---|---|---|---|
| 回复质量 | 启用经验模板实例的回复采纳率 | 相对未启用提升 **≥ 15pp** | 采纳信号（新增）+ A/B |
| 故障 | 舰队 P0 故障自愈率 | **≥ 60%**（playbook 自动修复或告警前置兜住） | M6 心跳/告警 + 故障回路 |
| 故障 | 相同错误族重复发生率 | 环比降 **≥ 30%** | 错误签名聚类 |
| 成本 | 舰队单条 API 成本中位数 | **≤ ¥0.025** 且月环比降 **≥ 5%** | S3 用量计量 + 成本回路 |
| 使用 | Roadmap 中由使用数据驱动的决策占比 | **≥ 30%** | 使用分析报告 |
| 业务 | 启用学习的客户续费率 | **≥ 90%** | 续费数据 + A/B |

## 2. 能学什么 vs 不能学什么（边界）

> 总原则（10 分卷铁律的工程落地）：**云侧永不出现"可还原到个体客户/单条对话"的数据。** 上报管线的结构本身就是边界：本地只产聚合桶，云侧只收聚合桶。

### 2.1 边界总表

| # | 数据维度 | ✅ 可聚合（脱敏统计） | ❌ 禁止聚合（学习边界外） | 边界规则 / 工程处理 |
|---|---|---|---|---|
| E1 | 错误事件 | 错误码/错误类型（VLM 识别失败、窗口异常、RPA 失败、API 超时、自循环）、归一化错误签名、频率、时间分布、引擎版本 | 错误发生时屏幕内容、OCR 文本、关联对话原文 | 特征提取只保留结构化错误签名；截图/OCR 默认不落盘、不上报 |
| E2 | 会话用量 | 会话量/消息量/回复量/skip 量的**分桶统计**、按小时分布、响应延迟分位 | 消息内容、回复原文、联系人维度数据 | 只报计数分桶，不报个体事件；最小粒度=实例+天 |
| E3 | 功能热度 | feature flag 状态、各功能（F1–F10）触发次数、启用率 | 功能触发时的具体输入输出 | 只报功能 ID + 计数，不带上文 |
| E4 | 接管 | 接管次数、reason 分布（explicit_human/complaint/price_sensitive/…）、处理时长分桶 | 接管时对话上下文、联系人、被接管原因原文 | 只报 reason 计数 + 时长分桶（F2 已有字段） |
| E5 | 回复采纳 | 采纳/修改/拒绝的计数与比率 | 修改后的最终回复文本、原 AI 回复文本 | 需**新增"回复采纳信号"**（见 3.4 与 6.2） |
| E6 | 成本 | 按模型/场景聚合的 token 用量、单条成本、延迟、成功率分布 | 单次请求的 prompt/输出、模型输出原文 | 只报聚合分布（复用 S3 计量） |
| E7 | 经验卡片模板 | 归一化 scenario（行业语义类型）、**通用化** guidance/rationale、卡片使用/成功统计 | 客户专有实体（品名/人名/地名/手机号/联系方式）、原始 evidence trace、含客户数据的卡片 | 上报前过"实体剥离 + 通用化"管线，人工抽检（见 4.3） |
| E8 | 告警/健康 | 心跳、宕机、告警事件计数、自愈动作类型 | 告警关联的屏幕画面 | 沿用 M6，不扩展内容字段 |
| E9 | 客户信息 | —（一律不采集） | 姓名/昵称/手机号/微信号/地址/邮箱/画像标签/消费记录/客户档案 | 字段级黑名单；上报管线结构上不触碰客户 store |

### 2.2 三条"物理边界"（写进代码，不靠自觉）

1. **上报管线无客户数据通道**：遥测聚合器只读"行为事件流 + 用量计量 + 告警"，不读 `CustomerStore / KnowledgeStore / worktrace/customers/*`。客户数据与遥测数据在本地就是两个数据域。
2. **字段白名单而非黑名单**：遥测 schema 是"白名单允许字段"，新字段需评审放行；不采用"全量采集后删敏感字段"的黑名单思路（黑名单漏一个就出事）。
3. **最小粒度 = 实例 + 天**：云侧不接受任何细于"客户 License + 自然日"的维度；同一行业桶不足 k（k≥5）个实例时并入"其他"，防止小样本反推。

## 3. 四个学习回路

> 共性骨架：**本地产生脱敏特征 → 云侧聚合 → 产出可回灌资产 → 回灌到全部/新实例 → 度量效果 → 再优化。** 四个回路各自闭环，共享同一套上报/回灌基础设施（第 5 节）。

### 3.a 故障学习（Fleet Reliability Loop）—— 反失败 playbook

**目标**：让"某个实例踩过的坑"不再让第二台实例踩。

```
本地：错误事件流（引擎各分支 error/skip/超时）
  → 特征提取：归一化错误签名（错误码 + 类型 + 上下文元数据 + 引擎版本）
  → 脱敏聚合桶（E1）
云侧：Fault Clusterer 错误聚类 → 错误族
  → 生成三类资产：
     ① 反失败 playbook（自动修复脚本/自愈步骤，如"窗口异常→重登微信→重启引擎"）
     ② 告警规则（新增/调阈值，如"同一错误 10 分钟 5 次→告警"）
     ③ 产品修复工单（高频错误族 → 进 bug 排期）
回灌：playbook 进看门狗（M1 自愈脚本库）、告警规则进 M6、热修复走版本下发
度量：自愈率、告警误报率、相同错误族重复发生率
```

**回灌生效方式**：playbook 以"自愈脚本包"下发到值守机，看门狗在下次遇到同签名错误时优先尝试；规则类进入 M6 告警引擎即时生效（可灰度）。

**KPI**：P0 自愈率 ≥ 60%；相同错误族重复发生率环比降 ≥ 30%；告警误报率 < 20%。

### 3.b 使用学习（Usage / Prioritization Loop）—— 产品迭代优先级

**目标**：用全舰队的"脚投票"决定产品往哪走。

```
本地：功能触发计数、feature flag 状态、会话生命周期、流失信号
  （活跃度下降、连续 skip、多轮转接、7 天未登录）
  → 用量/热度聚合桶（E2/E3）
云侧：Usage Analyzer
  → 功能热度排名、留存漏斗、按行业分桶用法分布
  → 输出：产品迭代建议（砍/加/优化）、按行业默认配置包、onboarding 改进点
回灌：配置包（人设/知识库/路由/接管阈值的行业默认值）→ 新实例初始化时一键套用
度量：功能使用率、周活跃实例、新实例激活率、流失预警命中率
```

**决策纪律**：砍/加功能必须有数据依据——功能连续 2 个周期使用率垫底且无战略价值 → 建议砍；同类流失信号集中 → 建议加 onboarding 引导。90 天目标：Roadmap 中 ≥30% 决策由本回路数据驱动。

### 3.c 经验学习（Experience / Template Loop）—— 核心差异化

**目标**：把单实例"越用越懂某客户业务"的过程性记忆，经客户同意匿名化后，沉淀为行业知识模板库，回灌给新实例——让新客户第一天就拥有老客户的成熟经验。

```
本地：工作记忆引擎（L3）产出的经验卡片 ExperienceCard
  → 客户同意（DPA 遥测条款 + 产品开关）后进入"模板化管线"：
     scenario 归一化为行业语义类型（如"询价后沉默""售后投诉升级""大促催付"）
     guidance 去实体化（剥离品名/人名/地名/价格）
     rationale 通用化（保留判断逻辑，去掉专有上下文）
     evidence 剥离（不上报原始 trace 引用）
  → 带行业标签 + 卡片成功率统计 的脱敏模板桶（E7）
云侧：Template Library
  → 聚类 → 行业知识模板库（如"电商客服话术最佳实践"）
  → 人工审核质量门（业务负责人确认/修改/驳回——沿用学习模式第⑤步）
  → 版本化管理（templateVersion，可回滚）
回灌：作为"可配置模板"下发；新实例在管理后台 **opt-in** 导入
  → 导入后进入 PromptAssembler 第 12 段（memory/经验段）注入运行
  → trace 记录引用 → 卡片成功率自动统计（闭环）
度量：模板采纳率、启用模板后回复采纳率提升、接管率下降、卡片成功率
```

**为什么是护城河**：Mem0/Letta 做"对话事实记忆"，没人做"过程性记忆模板"；中文企业场景（电商/医美/教育/本地生活）的行业经验语料全球零竞争（learn 规划 Phase C 的语料资产）。竞品可以抄功能，抄不走"50 家真实客服场景沉淀下来的行业话术库"。

### 3.d 成本学习（Cost / Routing Loop）—— 压单条成本

**目标**：用全舰队的成本分布，优化模型选择与路由策略。

```
本地：按模型/场景聚合的 token 用量、单条成本、延迟、成功率（E6）
云侧：Cost Optimizer
  → 全舰队成本分布、模型性价比矩阵（同场景：成本 vs 质量代理指标）
  → 路由策略建议（如"简单咨询→轻量模型、复杂售后→强模型"）
回灌：模型路由规则/默认模型/配额 配置下发（M2 配置中心承载）
度量：单条 API 成本中位数、成本/质量比、路由正确率
```

**工程约束**：成本优化不得牺牲回复质量——每次路由策略调整都走灰度（先 5% 实例，看采纳率不回退再全量），且质量代理指标（采纳率）是硬闸门。

## 4. 隐私保护技术方案

> 对齐 10 分卷 D1–D16 文档包；本节是工程实现细节。核心主张：**"云侧只收聚合统计"是设计事实，不是承诺。**

### 4.1 同意机制（两层）

| 层 | 载体 | 内容 |
|---|---|---|
| 合同层 | **DPA 遥测条款**（D5 新增附录） | 明确约定"匿名化学习数据"的范围（第 2 节表）、用途（产品迭代/行业模板/成本优化）、不包含聊天原文与个人信息、可关闭 |
| 产品层 | **管理后台「学习与遥测」开关** | 默认**关闭**（opt-in）；开启时展示"当前会上报什么"的可读清单；可随时关闭，关闭后停止上报并在本地清理待上报缓存 |

### 4.2 去标识化与匿名化（上报前，本地完成）

- **字段级过滤**：白名单 schema（2.2），非白名单字段物理丢弃。
- **PII 检测双保险**：正则（手机号/身份证/银行卡/邮箱/地址）+ 模型二次识别，命中即从特征中剥离；抽检率 ≥ 5% 样本由人工复核。
- **k-匿名**：行业/规模等分桶维度 k≥5，不足则并入"其他"（2.2-③）。
- **身份不可反推**：`profile_hash = HMAC(profile_id, 盐)`，盐在云侧密钥库，实例侧不可逆；客户 License 维度只用于聚合分桶，不用于画像。

### 4.3 经验卡片的"通用化"管线（E7 专用）

```
原卡片（本地，含客户上下文）
  → ① 实体剥离：正则+模型识别并剔除品名/人名/地名/价格/联系方式
  → ② scenario 归一化：LLM 将触发条件映射到行业语义类型（受限枚举，非自由文本）
  → ③ guidance 通用化：改写为"脱离具体客户、可复用到同行业"的表述
  → ④ 人工抽检放行：进入云侧模板库前过质量门（3.c）
```

**红线**：一张卡片若无法完成①②③，则**不上报**（宁可少，不可错）。

### 4.4 聚合统计而非个体

- 云侧只收"聚合桶/直方图"（每小时由本地合并生成），无个体事件流。
- 计数型指标默认加 **Laplace 噪声（差分隐私，ε≈2.0）**——对"接管次数/错误次数/采纳率分子"等敏感计数生效，统计结论不受影响，但单个实例贡献不可精确还原。差分隐私作为可选增强，第一批模板库上线时启用。
- 已聚合数据按"实例 + 天"保留，滚动 90 天，到期自动删除或二次匿名化。

### 4.5 数据最小化与删除权

- **最小化**：只收"第 2 节表中 E1–E8 白名单字段"；遥测体量设计上限（每实例/天 ≤ 数百 KB）。
- **删除权（PIPL 47 条）**：
  - 客户关闭开关 → 本地停止采集 + 缓存清零；
  - 客户请求删除贡献数据 → 云侧删除该 License 的全部聚合桶与模板贡献（模板入库后即与贡献者**解除关联**，删除时仅清统计关联，不删除已通用化的公共模板——这与 DPA 约定一致）；
  - 合同终止 → 云侧删除该客户全部遥测数据，提供删除证明（10 分卷 3.6）。

### 4.6 与合规文档包的衔接

- D5 DPA 增加"学习遥测"附录；D1 白皮书增加"跨实例学习数据流图"；D16 验收清单增加"上报管线不触客户数据"自测用例（A 租户遥测中无法反推 B 租户任何内容）。

### 5.4 关键工程质量属性

- **不可用不影响主链路**：遥测/上报全部异步、可降级、可熔断；上报失败绝不影响值守引擎（沿用 FeatureHooks "关闭零影响"纪律）。
- **回灌灰度发布**：模板/规则按百分比灰度（5%→20%→100%），任一质量闸门回退立即暂停该版本下发。
- **可观测**：云侧有"学习系统自身的健康看板"（上报实例数、缺数据实例、回灌版本分布），防止学习系统静默死亡。

## 6. 度量闭环：如何证明"沉淀学习真的有效"

### 6.1 三层证据链

| 层 | 问题 | 方法 | 输出 |
|---|---|---|---|
| L0 单实例 | 我的实例学得怎么样？ | 本地 Eval harness（learn 规划已有）+ 卡片成功率统计 | 单实例"启用模板前后"采纳率/接管率对比 |
| L1 舰队 | 全局学习整体有没有用？ | 同质配对 A/B + 灰度下发（第 5.4 节） | 全局学习 vs 不学习的差值报告 |
| L2 业务 | 对续费有没有用？ | 续费率 / NPS / 留存 长期追踪 | 学习价值 ↔ 续费的因果证据 |

### 6.2 A/B 实验设计（回复质量回路为例）

**关键前提——新增"回复采纳信号"**：当前产品没有显式的采纳/修改/拒绝反馈（只有 F2 接管与 F3 VIP 确认）。需在 Phase 1 补一个轻量信号：人工接管后，比对"最终实际发送文本"与"AI 草稿"，一致=采纳，修改=修改，人工重写=拒绝；或在坐席 UI 加"采纳/修改"一键标记。**没有这个信号，回复质量回路无从度量，列为 90 天必做前置。**

```
假设：启用全局经验模板的实例，回复采纳率更高、接管率更低。

分组：按"行业 + 规模（坐席数）+ 启用时长"配对
  A 组：启用全局经验模板（opt-in 后自动获得行业模板）
  B 组：不启用（对照组，仅本地单实例自学习）
  N：每组 ≥ 8 家实例（90 天舰队 50 家可分）

度量指标（每周拉取）：
  主指标：回复采纳率（采纳/（采纳+修改+拒绝））
  次指标：接管率、响应时长、单条成本
  业务指标：试用→付费转化率、续费率（季度观察）

护栏：A 组采纳率若低于 B 组 → 停止该模板灰度，回滚模板版本。

防偏置：
  ① 配对而非随机：行业/规模差异会淹没信号，必须配对；
  ② 观察期 ≥ 2 周：模板注入有"冷启动"，头 3 天数据不纳入；
  ③ 追踪"模板来源标注"：trace 记录引用模板 ID，归因到具体模板而非笼统的"全局学习"。
```

### 6.3 因果归因与"学了到底改了谁"

- trace 层已有 `memoryRefs`（引用哪些经验卡片）——扩展到 `templateRefs`（引用哪个模板版本），让每个效果信号可追溯到具体模板。
- 使用学习/成本学习的证据：功能砍/加后对比"该功能的周触发量/流失率"；路由策略调整后对比"同场景单条成本 + 采纳率不回退"。
- 输出物：**《舰队学习双周报》**（内部）+ **《客户学习价值报告》**（对外，第 7 节）——这是把度量变成续约谈判材料。

## 7. 产品呈现：把"沉淀学习"变成可销售的差异化

### 7.1 管理后台「学习中心」页（G3 管理后台新增 Tab）

```
学习中心
├─ 概览
│   ├─ 我的学习状态：上报开关（默认关/opt-in）、本月已贡献学习数据量、最近同步时间
│   ├─ 我的价值证据：本实例 vs 同行业基准（采纳率 / 接管率 / 单条成本 / 响应时长）
│   └─ 最近学到的：本实例采纳了哪些舰队模板、各模板带来的提升（📎 模板#v3 引用次数）
├─ 模板库（行业经验模板）
│   ├─ 按行业浏览（电商/医美/教育/本地生活）→ 预览卡片（scenario/guidance/成功率）
│   ├─ 一键启用 / 停用（opt-in）；启用后可看"启用前后"对比
│   └─ 模板贡献：本实例产出的卡片进入公共库的进度（匿名化、可审核）
├─ 学习洞察
│   ├─ 功能使用热度（本实例 vs 舰队）→ "这个功能用的人多/少"
│   ├─ 故障健康（本实例故障、舰队同类错误告警、已自动修复记录）
│   └─ 成本分布（按模型、超量告警）
└─ 报告
    ├─ 月度《客户学习价值报告》（自动生成：本实例提升 + 舰队基准 + 建议）
    └─ 数据管理：关闭上报 / 删除我的贡献 / 导出我的学习数据
```

### 7.2 为什么这是续约理由（卖点翻译）

| 卖点 | 客户内心问题 | 产品回答 | 挂在哪个功能 |
|---|---|---|---|
| **越用越聪明** | "这套系统会不会一直那么笨？" | "您接入的第一天，就拥有全舰队同类客户沉淀的话术与经验（模板库），且本实例也在持续变聪明（学习中心价值证据）" | 模板库 + 价值证据 |
| **行业最佳实践** | "别的同行怎么做客服？" | "匿名化的行业经验模板库，等于把 50 家同行的成熟做法变成您的默认配置" | 模板库（3.c） |
| **别家踩过的坑您不踩** | "值守机半夜挂了怎么办？" | "故障学习：全舰队同类错误自动修复或提前告警，月报展示自愈率" | 故障回路 + 学习洞察 |
| **成本透明可优化** | "AI 会不会越用越贵？" | "成本学习：自动优化模型路由，学习中心展示单条成本走势与省了多少" | 成本回路 + 成本分布 |
| **价值可量化** | "我怎么向老板证明这钱花得值？" | "每月《客户学习价值报告》：采纳率↑ / 接管率↓ / 响应↓ / 成本↓，直接可转发" | 报告 |

### 7.3 对销售的"一页纸"定位

> **RichCat 不是越用越贵，是越用越聪明。** 别的 AI 客服买回去是孤岛，RichCat 是一个会学习的舰队——您的每台值守机都在从全行业同类场景的经验里变强（可关闭、可审计、数据不出境、不含聊天原文）。这既是续约理由，也是把"工作记忆"从技术概念翻译成客户能感知的"我的客服越来越懂行"。

### 7.4 90 天落地节奏（对齐 00 周历）

| 周 | 里程碑 | 验收 |
|---|---|---|
| W1–4 | 遥测聚合器 + 上报管线 v0（白名单 schema、脱敏、opt-in 开关） | 战略伙伴实例可上报脱敏桶；管理后台可见"学习与遥测"开关 |
| W2–6 | 回复采纳信号（人工接管后比对最终发送 vs AI 草稿） | 采纳率可统计 |
| W4–8 | 云侧故障聚类 + 反失败 playbook 最小版；回灌灰度框架 | 同类错误自动修复或告警前置；灰度发布可用 |
| W6–9 | 经验卡片模板化管线 + 行业模板库 v0（电商首版，人工审核） | 首批 10+ 张通用化模板入库；新实例可 opt-in 导入 |

| W9–13 | 学习中心页 + 月度《客户学习价值报告》 | 首份报告随 50 家客户交付；学习价值进入续费话术 |
