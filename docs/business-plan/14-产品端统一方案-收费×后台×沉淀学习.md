## 一、一张图：三件事，一个管道

你问的三件事——**收费、总后台、沉淀学习**——不是三个系统，是**同一个"云管控制面"的三副面孔**。它们共享同一条"元数据遥测管道"，区别只在消费端。

```
┌─────────────────────────── 客户侧（数据主权在客户） ───────────────────────────┐
│  值守机 Agent（Windows，继承 v1.1.0 全部 AI 内核）                                │
│  ├─ 自动回复 / CRM / 知识库 / 人设 / F1-F10 / 工作记忆引擎                        │
│  ├─ 遥测 SDK：本地脱敏聚合（聊天/截图零上行，只产元数据聚合桶）                   │
│  ├─ 本地学习：单实例内自学习（工作记忆、失败自愈、成本路由）                      │
│  └─ License 客户端：每 5 分钟心跳校验 + 命令捎带接收                               │
└───────────────┬──────────────────────────────────────────────────────────────┘
                │ 上行：心跳/用量/错误/告警（仅元数据，k-匿名聚合）
                │ 下行：心跳捎带命令（配置/升级/模板/路由策略，穿透 NAT）
┌───────────────▼──────────────────────────────────────────────────────────────┐
│  云管控制面（我方托管 SaaS 为主，高合规客户可选私有化）                          │
│  ├─ ① 计费引擎   → License 授权 / 用量计量 / 套餐升级 / 配额熔断        ← 收费  │
│  ├─ ② 舰队监控   → 所有值守机 在线/离线/健康 + 用量看板 + 错误流 + 告警  ← 总后台 │
│  ├─ ③ 聚合学习仓 → 故障/使用/经验/成本 四分析器 → 模板回灌                ← 沉淀  │
│  └─ ④ 管理后台 UI（舰队视图/用量/审计/学习中心/配置下发）                        │
└──────────────────────────────────────────────────────────────────────────────┘
```

**一句话**：聊天原文永远留在客户值守机；上云到控制面的只有"脱敏统计 + 报错签名 + 使用热度"。这三件事在合规红线内，共享同一条管线。

## 二、收费模式怎么设计

### 2.1 授权模型：按"坐席"授权，四态流转

| 项 | 设计 | 理由 |
|---|---|---|
| **授权单位** | **坐席**（1 值守账号 × 1 设备） | 成本与价值双收口：一个坐席 = 一条 API 成本线 = 一份可感知价值 |
| **四态流转** | 试用(14天) → 正式(1年) → 续费 / 过期 | 试用强制解锁，到期逼年付 |
| **在线校验** | Agent 每 5 分钟心跳，License 服务端校验 | 防扩散 + 保活探活一石二鸟 |
| **离线宽限** | 断网 ≤72h 正常；超时降级「仅人工接管 + 数据只读」 | 宽限客户体验，超时仍能逼缴 |
| **离线授权** | 云管旗舰版专属备用通道（不公开售卖） | 高合规/内网客户备用 |
| **防扩散** | 设备指纹 + 并发心跳检测 | 防止一 License 多设备复用 |

### 2.2 套餐结构（对齐创始人定向：订阅优先）

| 版本 | 定价/年 | 坐席 | 含云管 | 定位 |
|---|---|---|---|---|
| 社区版（开源） | 免费 | 1 | 无 | 引流/口碑 |
| **战略伙伴** | **¥1 万**（限前 10 家） | 5 | Lite | 种子换案例+迭代反馈 |
| **标准版（主推）** | **¥2 万** | 5 | Lite | 90 天走量核心（40 家目标） |
| 专业版 | ¥4.5 万 | 15 | **Pro** | 中型团队，抬高客单 |
| 旗舰版 | ¥8 万 | 30 | **旗舰** | 高客单 + 学习沉淀/SSO/SLA |
| 增购坐席 | ¥3,600/年/席 | — | — | 增购入口 |

**升级/降级**：升级按剩余天数折差补款；降级仅续费期生效（不产生负向波动）。

### 2.3 用量计量与超量计费（成本闸门 = 命门）

| 项 | 设计 |
|---|---|
| 基础额度 | **10,000 会话 / 坐席 / 年**（团队版月均 ~830 会话/坐席，够个人号客服中位量） |
| 超量费 | `max(0, 实际 − 剩余额度) × ¥0.08/会话` |
| 用量包 | 1 万会话 ¥680 / 5 万会话 ¥3,000（预购更便宜，引导增量预付费） |
| **硬封顶** | 用量达基础×1.2 自动**熔断**（停止自动回复，转人工接管）→ 防账单爆炸 |
| **内部成本闸门** | 单条综合成本 > ¥0.04 → 自动降级模型路由（国产优先）；> ¥0.08 → 强制限量 |

> 商业意义：计量既是**成本闸门**（守 API 毛利），也是**增购入口**（超量→用量包），还是**续费证据**（月度用量报告）。

### 2.4 云管溢价：总后台本身就是卖点

| 云管层 | 定价/年 | 内容 | 升级钩子 |
|---|---|---|---|
| **Lite** | 随订阅含 | 单客户自己的用量看板 + 基础告警 | — |
| **Pro** | ¥8,000 | 集中舰队看板、实时错误流、审计导出、月度服务报告 | 告警演示 / 审计闸门 |
| **旗舰** | ¥20,000 | + 跨实例沉淀学习、API、SSO、SLA | 学习价值报告（续约谈判） |

**升级引导**：告警就是最好的广告——客户第一次看到"凌晨 3 点宕机自动告警推送到手机"，就知道云管 Pro 值钱。

### 2.5 90 天最小收费闭环

```
W1-3  License + 收款通道（对公/发票）        → 能收费
W3-6  云管 Lite（心跳/用量看板/基础告警）     → 能看到
W6-8  用量计量 + 配额熔断 + 审计             → 能防亏
W8-10 云管 Pro + 月度报告                     → 能溢价
```

**100 万组合**：10 战略(¥1万) + 40 标准(¥2万) + 5 专业(¥4.5万) + 增购/用量包 = ¥100 万。

## 三、总的管理后台：看得到每台前端

### 3.1 四类遥测事件（Agent 上报的唯一语言）

| 事件 | 内容 | 用途 |
|---|---|---|
| `heartbeat` | 在线/版本/资源（CPU/内存）/值守机状态 | 保活、版本分布、离线告警 |
| `usage` | 会话数/消息数/接管次数/API token 成本（**仅统计**） | 用量看板、计费依据、成本闸门 |
| `error` | 枚举错误码 + stack_hash（去标识化）+ 白名单安全文案 | 错误流、故障聚类、自愈触发 |
| `alert` | 规则产出（宕机/掉线/视觉误判/模型超时）+ 防抖 | 实时告警推送 |

> 统一信封：`{event_id, event_type, producer, tenant_id, ts, payload}`。Agent 侧正则 + 本地模型双保险脱敏，**聊天原文、截图零上行**。

### 3.2 管理后台能力清单（决策者 demo 第一眼）

1. **全局舰队视图**：所有客户值守机 → 在线/离线/健康三色，一眼看全盘
2. **单客户用量看板**：会话量/接管率/响应时长/API 成本/功能热度
3. **实时错误流**：报错按客户/类型滚动，红色告警即时可见
4. **告警规则引擎**：宕机、掉线、异常阈值，推送钉钉/企微/飞书
5. **审计日志查询**：全操作留痕、可导出（对应 G4 法务闸门）
6. **配置模板下发**：人设/知识库/路由/阈值，多账号批量下发
7. **学习中心**（沉淀学习入口）：全局经验模板库、行业配置包、学习价值报告

### 3.3 关键架构决策（详见 12）

- **下行用"心跳捎带命令"而非长连接** → 穿透 NAT、天然支持离线升级、省一条连接
- **租户隔离**：tenant_id 全链路（证书→队列→存储）+ PostgreSQL RLS 双保险
- **扩容**：90 天单机容器栈扛 50 实例 → 500 实例仅 ~300 峰值 QPS，真正风险是**保留策略**（防存储无界）而非吞吐
- **升级下发**：semver + 通道 + Ed25519 签名；灰度 1台→5%→50%→100%，健康门禁自动暂停，Agent 双份+自检自动回滚
- **技术选型**：Go 网关 + Kafka + PostgreSQL16 + TDengine（心跳时序）+ Redis（在线状态）+ React 后台

## 四、跨实例沉淀学习：让所有财听猫反哺产品

### 4.1 能学什么 vs 不能学什么（边界表——合规红线）

| ✅ 可聚合（脱敏元数据） | ❌ 禁止聚合（PIPL 红线） |
|---|---|
| 错误签名、故障模式 | 聊天原文、回复原文 |
| 用量分布、功能使用热度 | 姓名/手机号/微信号 |
| 接管原因分布、回复采纳率 | 客户画像/档案 |
| API 成本分布、模型路由分布 | 截图、OCR 文本 |
| 通用化经验卡片模板（实体剥离后） | 任何可反推个体的数据 |

**三条物理边界**：① 上报管线**不读客户 store**（代码层隔离）；② **字段白名单**（schema 强制）；③ 最小粒度 = **实例+天**，行业桶 **k≥5** 才出聚合（不足不报）。

### 4.2 四个学习回路

| 回路 | 学什么 | 回灌什么 | 90 天目标 |
|---|---|---|---|
| **a. 故障学习** | 全舰队错误聚类 | 反失败 playbook → 看门狗自愈 + 告警规则 + 修复工单 | 自愈率 ≥60% |
| **b. 使用学习** | 功能热度/流失信号 | 产品迭代优先级 + 行业默认配置包 | 路线 ≥30% 数据驱动 |
| **c. 经验学习（护城河）** | 经同意的匿名经验卡片 | 行业知识模板库（人工审核）→ 新实例 opt-in 导入 prompt 第12段 | 回复采纳率 +15pp |
| **d. 成本学习** | 全舰队路由/token 分布 | 模型路由策略灰度下发 | 单条成本环比 -5% |

### 4.3 隐私技术方案（合规落地）

- **同意机制**：DPA 遥测条款 + 产品内 opt-in 开关（**默认关、可关、可删**）
- **去标识化**：PII 正则 + 本地模型双检；k-匿名；HMAC 身份哈希
- **聚合统计**：只给 k-匿名群组聚合，**永不回传个体**
- **差分隐私**（可选）：ε≈2，进旗舰版卖点
- **数据最小化**：白名单 schema + **90 天滚动留存** + 删除权 + 终止删除证明

### 4.4 闭环架构（本地学习 + 云侧全局学习）

```
本地：Trace → FeatureExtractor → TelemetryAggregator（脱敏聚合桶）→ 上报队列
云侧：学习网关 → 四分析器（故障/使用/模板/成本）→ 回灌配置中心
回灌：模板→prompt 第12段 / playbook→看门狗 / 告警规则→M6 / 路由策略→Provider
```

### 4.5 度量：证明"沉淀学习真的有效"

- 前置信号：新增**"回复采纳信号"**（人工接管后比对最终发送 vs AI 草稿）
- 配对 A/B：同行业同规模客户，启用全局模板 vs 不启用
- 归因：trace 加 `templateRefs` 精确到"哪张模板带来这次采纳"
- 护栏：**采纳率回退即停灰度**（不牺牲客户体验做实验）
- 交付物：月度《客户学习价值报告》→ 续约谈判材料 + 云管旗舰卖点

## 五、三件事如何咬合（CEO 视角的关键判断）

1. **共享一条遥测管道，零重复建设**：License 心跳、用量计量、故障告警、聚合学习——都是同一批 Agent 上报事件的消费端。上云成本极低。
2. **总后台是"系统 vs 工具"的分界**：企业买单看的第一个东西就是后台舰队视图——"我的每个客服号怎么样"。它是 demo 的临门一脚。
3. **收费和后台互相成就**：用量计量既是成本闸门（防亏）也是增购入口（赚钱）；后台告警是升级云管 Pro 的活广告。
4. **沉淀学习是护城河也是续费理由**：竞品能抄功能，抄不走"全舰队经验反哺"。但它必须可证明（采纳率 A/B + 学习价值报告），否则只是营销词。
5. **合规边界不是负担，是卖点**：坚持"聊天原文不离开客户值守机"→ 私有化/合规客户才能放心签——这直接支撑企业版客单价。
