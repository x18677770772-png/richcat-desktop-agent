# 04 · 企业销售打法：售前 → POC → 签约 → 回款

**Status**: Draft — In Review
**Author**: 售前工程师（SE）
**Last Updated**: 2026-08-20
**Version**: 1.0
**配套**: [01-商业策略与90天100万路径.md](./01-商业策略与90天100万路径.md) ｜ [02-产品企业级化路线.md](./02-产品企业级化路线.md) ｜ [03-财务模型与定价.md](./03-财务模型与定价.md)
**目的**：把"90 天 100 万"从目标翻译成逐单可执行的销售动作——每一单走完 决策链识别 → 售前发现（Discovery）→ 价值型 Demo → 范围受控的 POC → 商务谈判 → 回款 的完整闭环。本文档是销售/创始人/售前共用的一本作战手册。

---

## 0. 执行摘要（先给结论）

1. **不卖工具，卖业务结果。** 每一场 demo、每一份报价都要挂在客户可感知的 ROI 账上：少招夜班客服、回复延迟从 2 小时到 2 分钟、情绪风险不流失、客户被记住带来复购。报价用 03 的锚点，但话术永远先说账。
2. **技术胜出是商务胜出的前提。** 决策链里 IT 和安全有一票否决权。POC 过不了技术关，报价谈都谈不到。技术对话必须全程关联业务成果，不讲功能堆砌。
3. **POC 是赢单或输单的关键战场。** 80% 的销售失败发生在 POC 阶段：范围失控、成功标准模糊、没有决策关卡。本文档把 POC 设计成"开始前就定好二元结果"的结构化评估。
4. **决策链 = 一票否决者先搞定。** 每单先画决策链地图：谁拍板（老板/负责人）、谁否决（IT/法务/安全）、谁评估（一线客服主管/运营）。一票否决者不提前搞定，销售做到最后被无声否决。
5. **90 天节奏：前 30 天创始人全职销售跑通单子 SOP，后 60 天按 SOP 放量 + 企业单攻坚。** 订阅保底盘（30 家 × ¥1.2 万）+ 企业单达标盘（3 私有化 + 2 定制 = ¥60 万），双轨并行，回款 ≥ ¥60 万是现金红线。

## 1. 目标企业客户购买决策链与关键角色

### 1.1 三档决策链地图（先识别你面对的是哪种决策结构）

| 档位 | 典型客户 | 决策结构 | 决策链特点 | 决策周期 |
|---|---|---|---|---|
| **SMB 小微**（订阅主战场） | 私域电商操盘手、知识付费 IP、个体门店 | **单一决策人**：老板/操盘手本人 | 老板既是买单人也是使用人，决策快、无 IT/法务拦截；痛点是"客服太累/回复太慢" | 3-14 天 |
| **中型企业**（MSE 私有化主战场） | 医美/口腔/体检门诊、保险/房产/汽车销售团队、MCN/达人商务 | **老板/负责人拍板 + IT 评估 + 财务把关** | 负责人是 Champion，IT 管部署与安全问卷，财务管预算与合同；两票否决在 IT 和老板 | 7-30 天 |
| **大型企业**（企业定制/标杆单） | 品牌方私域部门、中大型零售/教培 | **群体决策**：业务 Sponsor + 技术评估组 + 采购 + 法务 + 安全 | 必须走招标/评估流程；法务和安全有独立否决权；Champion 必须在中层，否则流程推不动 | 30-60 天 |

### 1.2 关键角色 × 关注点 × 赢单策略（决策链角色卡）

| 角色 | 在决策链的位置 | 他们真正关心什么 | 赢单策略 | 埋雷问题（Discovery 中自然问） |
|---|---|---|---|---|
| **老板 / 操盘手本人** | 拍板人（SMB 与中型企业） | 少花人力、多成交、口碑不坏、睡得着觉 | 给总账：1 个夜班客服人力 6-10 万/年 vs 1.2 万/年的订阅；用 ROI 一页纸收口 | "您现在客服这块每个月/每年真实花销是多少？夜班和节假日怎么排班？" |
| **销售 / 客服负责人**（业务 Champion） | 推荐 + 使用 + 评估结果 | 团队效率、KPI（响应时长/满意度/转化）、不被投诉 | 把 Champion 变成内部销售：给他一个"让自己部门更好看"的方案；交付后给他能向上汇报的服务月报 | "您团队现在响应客户平均要多久？高峰时段漏消息/漏单的情况每月大概几次？" |
| **IT / 运维负责人** | 一票否决（部署/安全/兼容） | 能不能部署、是否安全合规、是不是又一堆运维负担 | 提前给：值守机规格、部署手册、安全白皮书、SLA 承诺（可用率 ≥ 99%、告警 ≤ 15 分钟）；演示时展示审计日志和部署向导 | "您对客户端软件有什么安全/准入要求？有没有现成的安全问卷我可以直接答？" |
| **法务 / 合规** | 一票否决（数据合规） | PIPL 合规、数据归属、审计留痕、AI 输出责任 | 给《数据隐私承诺书》《安全白皮书》、审计日志演示、数据归属条款；话术落到"全链路留痕、可导出、可脱敏" | "AI 回复的原文你们需要留痕到什么程度？敏感数据（手机号/身份证）有脱敏要求吗？" |
| **财务 / 采购** | 流程把关（预算/合同/账期） | 预算有没有、年付还是月付、开票、合同条款 | 报价单提前拆解清楚（软件 + 实施 + 用量），年付折扣逼单，首付 40-50% 条款写进合同 | "这个预算大概在哪个区间，是走年费还是项目制？审批流程里有硬性供应商要求吗？" |
| **一线客服 / 运营主管** | 影响者（好用才用） | 上手简单、不再熬夜、别被 AI 抢饭碗 | 让他们在 POC 里亲手操作接管和话术配置，明确"AI 干粗活、人干需要判断的活"；给值班手册 | "你们现在最烦的重复劳动是什么？哪些消息你们宁可不自己回？" |

### 1.3 决策链作战规则

1. **先画链再约会。** 每个商机第一周内产出"决策链地图"：谁拍板 / 谁否决 / 谁 Champion / 谁影响。画不出来 = 商机质量不达标，降级处理。
2. **一票否决者最早约。** IT 和法务的否决是最贵的销售失败——被否决往往发生在签约前夜。在首次 Demo 就邀请 IT 参加，先解决部署和安全问题。
3. **Champion 要放在中层。** 大型企业没有中层 Champion 流程推不动；SMB 的 Champion 就是老板本人。
4. **每个角色一份材料。** 老板 = 1 页 ROI 总账；IT/安全 = 部署手册 + 安全白皮书 + 审计演示；客服主管 = 操作演示 + 值班手册；财务 = 报价单 + 发票/账期说明。
5. **记录在评估笔记里。** 每个商机维护《评估笔记》：技术环境 / 决策者态度（支持/中立/怀疑）/ Discovery 发现 / 竞争态势 / POC 策略。每次触达后更新。

## 2. POC 设计与话术（用现有 v1.1.0 快速演示价值）

### 2.0 核心原则（POC 开始前必须内化的三条）

1. **POC 不是免费试用，是结构化评估**——有二元结果（通过/不通过），成功标准在配置第一台机器之前就与客户书面确认。
2. **Demo 先量化问题，再展示产品；先展示结果，再反向拆解过程。** 客户关心"得到什么"在先，"怎么实现的"在后。
3. **POC 激进控制范围。** 一个聚焦的 POC 证明一件关键的事，胜过发散的 POC 什么都没证明。客户要加测 X，回答："完全可以，放第二阶段。我们先把核心场景打穿，给你一个清晰的决策点。"

### 2.1 现场 Demo 设计（一次性会议，30-45 分钟）

**开场 3 分钟：量化问题（用 Discovery 里客户自己的数据复述痛点）**
> 话术模板："您提到团队每周花 X 小时在微信上反复回复相似问题，夜班/节假日无人值守，客户过了 24 小时还没回复可能就流失了。我现在演示的是把这个时间缩到秒级——请先看结果。"

**高潮 1：先展示终态——值守看板与日报（F6）**
- 打开服务日报：今天的服务客户数、VIP 动态、接管事件、待跟进清单。
- 话术："这是 AI 昨晚独立值守产生的日报。凌晨 2 点 3 位客户的消息是 AI 回的，其中一位 VIP 用的是专属话术，另有一位情绪不满的被识别出来并留到今早给您跟进。"

**高潮 2：工作记忆（差异化护城河）——先给客户看"被记住"的效果**
- 打开某位老客户的档案，展示跨会话长期记忆（上次聊过什么、偏好、待办）。
- 话术："客户不会换掉一个记得他全部历史的'客服'。您看这条回复，它把客户上个月提过的需求直接关联进来了——这是纯视觉方案 + 工作记忆引擎才做得到的事。"

**高潮 3：情绪/风险识别（F5）与人工接管（F2）——老板最怕的风险**
- 演示一条"不满/退款意向"消息被识别、客户被打标、风险提醒弹出。
- 话术："情绪风险不是'回得快'能解决的，是'识别得对'。AI 不硬扛，识别到风险立刻转人工接管并留痕。"

**反向拆解（客户被结果打动后）：再讲配置**
- 人设切换（5 种人设 + 自定义）、知识库（F9 分级）、多角色路由（F4）、VIP 差异化（F3）。
- 话术："这些 3 分钟内可以配置好，用的是您自己的话术风格。不是让 AI 自由发挥，是严格按您的业务规则回。"

**证据收尾：**
- 用行业案例或基准数据收尾："同行业的 X 客户，上线 30 天把夜间回复延迟从 2 小时压到 2 分钟，转人工率下降 40%。"

**听众双路径准备：** 技术评估者（IT）走架构与安全深潜（视觉 RPA 原理、数据加密、审计日志、值守机规格）；业务 Sponsor 走结果与时间线（ROI、上线周期、SLA）。当全场注意力转向，跟随能量走。

### 2.2 三档 POC 设计（按客单价与客户规模分档）

**档位 A：轻量验证型 POC（订阅线，客单 ¥1.2 万/年，周期 5-7 天）**
- 适用：SMB 小微、决策人是老板、决策快。
- 范围：1 个账号接入真实微信，AI 自动回复 + 客户建档 + 工作记忆，跑满 7 天。
- 成功标准：
  | 标准 | 目标 | 衡量方式 |
  |---|---|---|
  | AI 自动回复采纳率 | ≥ 80%（无需人工改稿） | 日报统计 AI 回复条数 / 总回复条数 |
  | 夜间值守 | 凌晨 0-8 点客户消息全部有响应 | 日报接管记录 + 客户消息时间戳 |
  | 客户建档 | ≥ 95% 新客户建立档案 | 客户列表增量 |
  | 工作记忆生效 | 复购客户被"记住"≥ 3 例 | 人工核验会话上下文 |
- 决策关卡：第 7 天给一份"7 天值守战报"（服务量/接管/风险/复购线索），老板当场决定是否年付。

**档位 B：标准 POC（MSE 私有化线，客单 ¥3.8-12.8 万，周期 14 天）**
- 适用：中型企业、老板/负责人拍板 + IT 参与评估。
- 范围：3-5 个客服账号值守机部署；知识库 + 人设按客户业务配置；情绪风险告警推送（企微/钉钉机器人）；接管流程留痕。
- 成功标准：
  | 标准 | 目标 | 衡量方式 |
  |---|---|---|
  | 多账号稳定值守 | 连续 7 天 0 人工干预、掉线自愈率 ≥ 95% | 值守机日志 + 心跳 |
  | 回复时效 | P95 响应 ≤ 60 秒（含 VLM 视觉链路） | 后台统计 |
  | 情绪风险识别 | 测试集不满/投诉意图召回率 ≥ 90% | 用客户真实历史消息回测 |
  | 人工接管闭环 | 接管事件响应（分给人）≤ 5 分钟 | 接管记录 |
  | 审计留痕 | 全操作可回溯、可导出 | IT 验收演示 |
- 决策关卡：第 14 天最终汇报，客户基于以上标准做 GO / NO-GO。GO → 商务谈判（首付 40-50% 后启动正式交付）。

**档位 C：企业定制 POC（客单 ¥15-30 万，周期 21-30 天）**
- 适用：大型企业、群体决策、需要走采购/招标流程。
- 范围：私有化部署（客户内网）+ 知识库批量导入 + 对接已有 CRM/工单（API v1，若可用）+ 团队接管治理（值班表/管理者介入）。
- 成功标准：在 B 档基础上增加"与现有系统对接成功率 100%"、"值班表接管分配正确率 ≥ 95%"、"月度可用率报告可自动生成"。
- 决策关卡：分两个 Gate——G1（第 14 天技术验收，技术评估组签字）→ G2（第 21-30 天商务审批，采购 + 法务 + 老板）。

### 2.3 POC 执行模板（每个 POC 必须产出一份）

```markdown
# POC：[客户名称]

## 问题陈述
[一句话：这次 POC 要证明什么]
例：证明财听猫能在[客户名]的客服环境下，实现 7×24 无人值守自动回复，
将夜间响应延迟从 2 小时压到 60 秒内，并在情绪风险出现时秒级转人工。

## 成功标准（开始前与客户书面确认）
| 标准 | 目标 | 衡量方式 | 数据来源 |
|---|---|---|---|

## 范围——包含/排除
包含：[账号数、功能清单、集成范围]
明确排除：[不测的内容及原因——如多账号并发、API 深度对接]

## 时间线
- 第 1-2 天：环境搭建与配置（值守机、知识库、人设）
- 第 3-7 天：核心场景值守（跑真实业务）
- 第 8 天：与客户中期回顾（确认没有偏离成功标准）
- 第 9-13 天：优化 + 边缘场景测试（情绪风险、接管、VIP）
- 第 14 天：最终汇报 + GO/NO-GO 决策会议

## 决策关卡
客户基于以上成功标准做 GO / NO-GO；GO 即进入商务谈判。
```

### 2.4 POC 话术要点

- **成功标准确认话术**："为了不让这次验证含糊，我们把'通过'具体定义为这三条指标。如果三条全过，咱们进入商务；任何一条没过，我们如实告诉你原因和改进方案。这样你我的决策都是清楚的。"——模糊的成功标准 = 输掉 POC。
- **范围控制话术**："您提的这个场景非常合理——它在我们的第二阶段支持里。咱们先把核心场景（自动值守 + 接管 + 风险）打穿，给你一个清晰的决策点，不要 14 天过去什么都测了一点、什么都没证明。"
- **中期回顾**：第 8 天必须主动做，不要等客户发现偏离。"目前进度：标准 1 已过，标准 2 还差 X，原因是 Y。下周这样处理。"——防"客户中途改了标准"。
- **视觉稳定性话术（IT 关心）**："我们承诺值班时段可用率 ≥ 99%、异常告警 ≤ 15 分钟、关键流程人工确认兜底。POC 里会输出一份可用性报告给你看真实数据，而不是让你信承诺。"

## 3. 常见异议与应对（技术层根因解决）

> 原则：**技术异议先找根因。** 客户说出来的话往往不是真问题；回答表层问题就输了。每条异议用"他们说的 → 真实含义 → 应对"三层拆解。

### 3.1 安全与合规类（IT/法务一票否决区）

| 客户说的 | 真实含义 | 应对（话术 + 证据） |
|---|---|---|
| "AI 会不会把客户资料泄露出去？" | "我们的客户数据你能不能保证安全？" | 讲数据主权与安全基线：客户数据本地存储（SQLite 加密 + Key 加密托管）、管理后台登录认证 + RBAC、日志自动脱敏（手机号/身份证）、传输 TLS。给《安全白皮书》与《数据隐私承诺书》。 |
| "你们服务器上能看到我们的对话吗？" | "我不想让第三方碰我的业务数据。" | 私有化部署：值守机在客户侧，管理后台可部署客户内网，我方只托管 License 与可选告警通道。数据归属写进合同。 |
| "AI 回复出错了谁负责？" | "出问题不能追责，我不敢用。" | 全链路审计：每条 AI 回复原文留痕、接管事件留痕、可导出可脱敏。F5 情绪风险 + F2 人工接管兜底——AI 不硬扛，风险秒级转人工。SLA 条款里承诺可用率。 |

### 3.2 稳定性类（IT/运维）

| 客户说的 | 真实含义 | 应对 |
|---|---|---|
| "会不会掉线了没人知道？" | "客服电话断了没人管，这比不用还糟。" | 值守机 Agent 化：开机自启、崩溃自愈、看门狗；心跳上报 + 全局健康页；异常告警 ≤ 15 分钟推送到企微/钉钉。SLA 承诺值班时段可用率 ≥ 99%，POC 输出月度可用性报告。 |
| "视觉识别会不会点错/误判？" | "你们方案可靠吗？会不会点到不该点的？" | 承认局限 + 兜底机制：视觉 RPA 偶发误判有自愈 + 告警兜底；接管阈值按客户业务校准；F2 保证"AI 不做高风险判断"。给真实 Eval harness 对比报告（识别准确率数据）。 |
| "你们才 v1.1.0，太年轻了。" | "你们没经过大规模验证，我凭什么信？" | 不硬撑：展示 QA 报告（F1-F10 全套通过）+ POC 真实值守数据 + 路线图（MSE 骨架 W8 内完成）。POC 本身就是对稳定性的验证——让数据说话。 |

### 3.3 效果类（业务负责人/一线）

| 客户说的 | 真实含义 | 应对 |
|---|---|---|
| "AI 回得能有人味吗？会不会得罪客户？" | "客户体验是口碑，我输不起。" | 5 种人设 + F10 情绪价值提示词体系（专业感 + 人感）；F3 VIP 专属话术；F5 情绪风险秒级识别转人工——AI 不处理高风险情绪，人工兜底。Demo 现场用客户真实消息展示。 |
| "机器人回消息客户会觉得被敷衍。" | "我要的是'看起来像真人'。" | 纯视觉 = 完全原生微信操作，消息从真实微信账号发出，无机器人标识、无接口痕迹。回复风格完全按客户话术配置。 |
| "客户太多，AI 会不会漏单？" | "漏一个客户 = 丢一单钱。" | 待跟进提醒（F7）、客户建档 95%+、VIP 差异化不漏 VIP；日报把当日服务客户数与漏接情况透明化。 |

### 3.4 成本类（财务/老板）

| 客户说的 | 真实含义 | 应对 |
|---|---|---|
| "一年 1.2 万（订阅）/ 6.8 万（私有化）贵了。" | "你的价值我看不到，或我有更便宜的选项。" | 报 ROI 账：1 个夜班客服人力 6-10 万/年，1 套系统替代 0.5-1 人夜间值守；回复从 2 小时到 2 分钟对流失率的挽回。对比市场锚点：SCRM 基础版 ¥9,800-19,800/年（探马/尘锋），私有化大厂 10-30 万，我们只锚 1/3。 |
| "AI 调用还要花 API 钱？" | "隐性成本没底。" | 用量透明：年费含基础额度，超出按用量包计费（¥0.05-0.10/会话，含给客户留缓冲）。用量报表可见可配额，不让客户有无限账单的恐惧。 |

### 3.5 封号担忧类（老板最怕的合规雷）

| 客户说的 | 真实含义 | 应对 |
|---|---|---|
| "用这种工具会不会被封号？" | "封号 = 客户全没了，这个风险我扛不起。" | **这是视觉方案的战略主场，不要含糊。** 话术："我们是纯视觉方案——AI 像真人一样坐在电脑前看屏幕、点鼠标、打字，不调用任何微信接口/协议，不碰任何官方禁用的 API。行为路径与真人操作一致，这是现有唯一能同时搞定群聊 + 合规的方案。" + 拟人化节流：主动触达内置每日上限 + 人工确认开关，不做机器化轰炸。 |
| "官方 iLink 不是更安全吗？" | "官方通道是不是更靠谱？" | FIA 定位：官方 iLink 协议确实合规，但**只能 1v1、不能群聊**——你们的核心场景（群聊客服）它根本覆盖不到。WeChatFerry 类第三方协议已停更，有封号与维护风险。我们是唯一覆盖"个人号 + 群聊 + 视觉 + 合规"全场景的方案。 |

### 3.6 竞品/大厂类（业务负责人）

| 客户说的 | 真实含义 | 应对 |
|---|---|---|
| "企微官方客服不是也有 AI 吗？" | "为什么不直接用大厂方案？" | 不贬低，重构："企微官方做 1v1 和服务号做得很好。但你们的场景是**个人号 + 群聊 + 多账号**——这是企微官方 API 覆盖不到的地带，也是我们存在的理由。我们不做企微的替代品，我们补它的盲区。" |
| "你们竞品展示了 X 功能。" | "你们能做吗？还是让我继续比？" | 不接竞品框架，回到客户需求："那个功能我们也有/我们这样解决。但更重要的是回到你们的三个核心场景——我们来对照一下谁的方案在你们的环境里交付更快、运维更省。" |

### 3.7 异议管理纪律

1. **每条异议记录到评估笔记**，标注客户角色（谁提的）——同一异议在老板和 IT 嘴里要答不同内容。
2. **不编造能力。** "这个目前没有原生支持，我们的客户是这样解决的，产品路线图上是这样规划的。"不诚实的回答会抹掉十个诚实的。
3. **FIA 框架（事实-影响-行动）处理所有竞品对比**，不靠 FUD。输区（如有）承认并重构回客户优先级。

### 4.1 渠道类型与分工（谁在什么时候帮我们卖）

| 渠道类型 | 画像 | 为什么愿意卖 | 合作模式 | 典型客单 | 需要我们的赋能 |

| **私域/电商代运营服务商** | 接客户私域代运营项目的乙方 | 用 RichCat 当交付引擎，降低自己人力成本、提升毛利 | 转售/白标，RichCat 作为其交付工具 | ¥2-5 万/项目（软件部分） | demo 环境 + 话术 + 部署培训 |
| **营销/广告代理公司** | 服务本地商家的代理 | 客户追问"客服自动化"，代理需要有产品回答 | 转售 + 分佣 | ¥1.2-3.8 万/单 | 一页纸方案 + 快速 demo 包 |
| **行业 ISV / 软件服务商** | 医美/教育/本地生活行业 SaaS 伙伴 | 补足"微信侧客服"能力缺口，增强自己产品 | 集成/白标 | ¥3.8-12.8 万/项目 | API 文档 + 联合方案模板 |

| **系统集成商（SI）** | 有企业 IT 客户资源的集成商 | 客户要求私有化部署，SI 负责交付 | 白标 + 实施分包 | ¥6.8-15 万/单 | 部署手册 + 实施培训 + 后端支持 |

### 4.2 渠道政策（商务框架）

- **渠道结算价** = 标价 70%；渠道分佣 30-50% 由渠道侧决定（给渠道留足利润，渠道才出力）——与 03 定价体系一致。
- **报价底线**：渠道最低不得低于标价 70%，防渠道压价伤害品牌与直销价格体系。
- **回款规则**：渠道负责客户回款或由我方收款后按回款结算佣金（推荐后者，现金流可控）。佣金按实际回款到账发放，不按签约。
- **防串货**：渠道客户归属登记制（先登记客户名单再跟单），一单一记。

### 4.3 渠道赋能包（不给渠道赋能 = 渠道不会卖）

**必须交付给渠道的东西：**
1. **标准演示包**：可重复 demo 环境（演示账号/话术/数据）+ 30 分钟 demo 脚本（含话术逐字稿）+ 常见异议应答卡。
2. **一页纸方案**（MSE 价值主张）+ 行业案例集（电商/医美/教育各 2-3 个）。
3. **POC 模板**（本文件第 2.3 节）+ 报价单模板 + 合同模板（含 SLA、数据归属条款）。
4. **渠道快速上手培训**：1 次线上培训（部署 + 演示 + 商务），通过考核才开通渠道号。

### 4.4 渠道 SOP（90 天滚动）

| 阶段 | 动作 | 验收 |
|---|---|---|
| D1-15 | 接触 10 家目标渠道，签约 3 家（给演示包 + 分佣） | 渠道意向 3 家，首批出单 1-2 |
| D16-45 | 渠道放量至 5-6 家；渠道出单 5+；月度渠道复盘（跟进数/演示数/转化） | 渠道贡献营收 ≥ 20% |
| D46-90 | 渠道 8-10 家，贡献 30%+ 营收；加码激励（季度达标返点） | 渠道营收 ≥ 25 万 |

### 4.5 渠道风险与对策

- **渠道出单慢/不专业**：只给"会卖的"赋能；90 天渠道贡献不达标 → 重仓直销 + 服务代运营兜底（01 已定）。
- **渠道压价**：价格底线写进协议，低于标价 70% 不成交。
- **渠道抢直销客户**：客户归属登记制，先登记先得。
- **白标质量**：白标只给成熟渠道 + 标准交付包，避免交付翻车砸品牌。

## 5. 90 天签约打法：线索 → 商机 → POC → 商务 → 回款

### 5.1 五步漏斗与周节奏（对齐 01/03 目标）

```
线索池 → MQL（加微+明确场景）→ Demo → 试用/POC → 签约 → 回款
```

| 环节 | 90 天总量 | 周均 | 转化率 | 判定标准（出口 Gate） |
|---|---|---|---|---|
| 线索池（私域+内容+渠道） | 4,000 | ~450 | — | 进入池即记录 |
| MQL | 1,200 | 135 | 30% | 加微 + 明确场景（"我们客服很累/回复慢/夜班没人"） |
| Demo（直播 1 对1） | 480 | 55 | 40% | 演示后产出"下一步行动"（试用/POC/报价），不是"回去讨论" |
| 试用/POC（14 天） | 220 | 25 | 45%→11% | POC 结束产出 GO/NO-GO 决策 |
| 签约 | 30 订阅 + 5 企业 | 3.5 订阅/周 | 试用→成交 11%+ | 合同签署 + 首付到账 |
| 回款 | ≥ ¥60 万 | — | 账期 ≤ 30 天 | 现金到账，超期停服 |

**周复盘会**（每周五 30 分钟，只盯 4 个数）：管道金额 / 新签 / 回款 / 各环节转化率。未达标环节下周前段补课。

### 5.2 分环节 SOP

**① 线索 → MQL（Qualify 快，别浪费创始人带宽）**
- 线索打分三问：① 有没有微信客服/群聊场景？② 付费人是不是老板/负责人？③ 痛点（人力/延迟/漏单）够不够痛？三问全中 → MQL，进 1对1；两中 → 进直播 demo 池；一中 → 内容培育，不消耗 1对1 时间。
- 工具：飞书多维表格即可，不自建 CRM（01 纪律）。

**② MQL → Demo（Demo 是过滤与教育的工具，不是最终目的）**
- 首推"群直播 demo"（一场 50-100 人），1对1 只给高意向（MQL 打分靠前）。
- Demo 必须产出**明确的下一步行动**：预约 14 天试用 / 启动 POC / 给报价。产出不了 = Demo 失败，不列入推进。
- 每场 Demo 记录到评估笔记：听众、情绪、异议、下一步。

**③ Demo → POC（POC 是决策工具，不是免费劳动力）**
- 用第 2 节的 POC 模板，成功标准书面确认后才启动。
- 订阅线用档位 A（5-7 天），私有化线用档位 B（14 天），企业线用档位 C（21-30 天）。
- 第 8 天中期回顾，第 14 天决策会议，产出 GO/NO-GO。
- **决策关卡纪律**：GO → 立即进商务；NO-GO → 复盘原因（标准没达标 / 范围失控 / 客户其实没预算），如实记录到赢输分析。

**④ POC → 商务（谈判窗口只有 7 天，别拖）**
- POC 刚 GO 时是谈判力最强时刻：价值刚被验证、客户处于兴奋期。超过 7 天情绪消退，谈判力衰减。
- 报价挂 ROI：用 POC 实际数据（接管率/响应时长/服务量）反推年节省与转化提升，报价 = 价值 × 折扣。
- 逼年付：年付 ≈ 10 个月费用，预付给折扣（03 定价）；to B 回款是生命线。
- 合同纪律（03 触发点规则）：
  - 企业单**首付 ≥ 40-50% 后才启动实施**；
  - **账期 ≤ 30 天，超期停服**；
  - 合同含 SLA 条款（可用率 ≥ 99%、告警 ≤ 15 分钟）、数据归属条款、数据销毁条款。

**⑤ 签约 → 回款（回款是 90 天验收红线）**
- 签约 ≠ 回款。签约 100 万但回款 60 万照样不及格（01/03 红线）。
- 回款节奏：年付/预付逼提前回款；企业单按里程碑收款（首付 40% → 上线 30% → 验收 30%）；
- 应收追踪表：每笔应收单列（金额/账期/责任人/催收动作），每周复盘。
- 超期动作：第 30 天提醒 → 第 45 天升级（创始人电话）→ 超期停服（已写进合同）。

### 5.3 90 天三阶段日历（对齐 01 Phase 1-3）

| 阶段 | 天数 | 销售动作 | 里程碑 |
|---|---|---|---|
| **Phase 1 冷启动** | D1-15 | 定价/合同/收款通道落地；种子 10-15 家换案例（免费/低价换案例 + 创始人手动陪跑交付）；渠道签约 3 家；试用 SOP 标准化 | 首批可引用案例；渠道 3 家；MQL 5+ |
| **Phase 2 首批付费** | D16-45 | 每周 1 场直播 demo + 2-3 篇内容；创始人每天 3-5 个跟进；渠道出单；订阅放量 | 订阅 15+，签约 ≥ ¥20-35 万；**D45 判定：订阅 <12 家 → 切服务代运营兜底** |
| **Phase 3 放量攻坚** | D46-90 | 企业 POC 3 个并行攻坚；渠道放量 8-10 家（贡献 30%+）；案例库 → 白皮书；企业单签约 2-3 个 | **签约累计 ¥100 万；回款 ≥ ¥60 万；付费客户 ≥ 28-35 家** |

### 5.4 单人带宽管理（创始人 = 唯一全职销售的约束）

| 杠杆 | 用法 |
|---|---|
| 直播 demo 覆盖 50-100 人 | 1对1 只给高意向 MQL，其余进直播池 |
| 渠道分流 | 渠道负责触达与初次演示，创始人只做高客单 POC + 商务 |
| 标准化物料 | 演示包/异议卡/报价模板/合同模板——复制，不重写 |
| 外包实施 | 轻交付（≤1 人日/客户）外包，创始人聚焦销售 |
| 确定性优先 | 每单判断"是否值得花 1 对1 时间"，不值得就直播/渠道/降级 |

### 5.5 商务谈判要点（技术 SE 与创始人/销售共用）

1. **锚点先于报价**：先摆市场锚点（SCRM ¥9,800-19,800/年、私有化 10-30 万），再报我方价格——我方式视觉+群聊+工作记忆的唯一方案，中位定价合理。
2. **价值先于价格**：先算 POC 的 ROI 账，再报价。客户问"能不能便宜点"，回答"按您的场景，这套系统一年给您省的是 X 万人力 + 挽回 Y 流失——我们的价格是它的零头"。
3. **让步要换东西**：价格折扣换年付预付 / 换 3 年长约 / 换转介绍——不要让价格凭空让步。
4. **输区不硬撑**：客户坚持某个竞品强项时，承认 + 重构回客户优先级："那个能力确实重要，对主要关注该场景的团队是强选项；对你们环境，[客户优先级]是主要驱动，这才是我们方案长期交付更多价值的地方。"

### 5.6 90 天验收红线（与 01/03 一致）

- 累计签约 ≥ ¥100 万；
- **回款 ≥ ¥60 万（现金红线，超期停服纪律）**；
- 付费客户 ≥ 28-35 家（订阅 30 + 企业 5）；
- 试用→付费转化率 ≥ 10-11%；
- 渠道 ≥ 8 家且贡献 ≥ 30%；
- 案例库 ≥ 20 个，其中可引用的量化案例 ≥ 10 个。

### 5.7 触发点与纠偏（不做一锤子买卖）

| 触发点 | 判定 | 动作 |
|---|---|---|
| D45 | 订阅 < 12 家 | 切换"AI 私域客服代运营"为主攻（卖结果兜底），保现金流 |
| D60 | 企业 POC 无一进入商务 | 企业单降级为订阅，目标下修至 60-70 万，如实通报团队 |
| 任意 POC | 成功标准偏离 | 第 8 天中期回顾纠偏；偏离不可挽回 → 提前终止，不烧时间 |
| 任意客户 | 首付 < 40% | 不启动实施（03 纪律） |
| 任意应收 | 账期 > 30 天 | 停服（合同条款） |
